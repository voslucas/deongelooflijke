# Site architecture

The entire site is `site/src/index.template.html` — a single HTML file with all CSS and JavaScript inline. No build tools, no frameworks, no runtime fetches except Google Fonts and episode data.

## Key design decisions

- **No server required.** Open `site/dist/index.html` directly in a browser.
- **Hash routing.** Route changes update `location.hash`; the popstate listener calls `route()`.
- **Data inlined at load.** A lightweight episode index (329 entries, light fields only) is embedded as `<script id="data" type="application/json">`. Heavy fields are fetched on demand.
- **Views are functions.** Each route corresponds to a function (`viewHome()`, `viewEpisode(e)`, etc.) that sets `app.innerHTML`. Always escape user/data text with `esc()`.
- **No chart libraries.** All visualisations are hand-drawn SVG via helper functions (`vbars`, `hbars`, `lines`, `scatter`, `spark`).

## Global data structures

```javascript
D        // {eps[], bios{}}  — raw embedded data from <script id="data">
EP       // Array of episode objects (D.eps with computed fields added)
REG      // EP.filter(e => e.n !== null)  — numbered episodes only
byKey    // {key: e}  — episode lookup by string key
byNum    // {n: e}    — episode lookup by number
TX       // {key: T}  — transcript T-object cache (populated on first load)
_EP_FETCH // {key: Promise}  — in-flight fetchEpisodeDetail promises
```

Each episode object `e` in `EP` gets these computed fields beyond what's in the data:

```javascript
e.key    // string key: "327" or "x<id>" for unnumbered
e.y      // year (from e.d)
e.vec    // TF-IDF cosine vector (for similarity)
e.kw     // top-10 keywords (computed if not already in data)
e.npoUrl // NPO episode URL (set after fetchEpisodeDetail)
e._loaded // true after fetchEpisodeDetail has run
e.an     // analysis object (set after fetchEpisodeDetail, if analysis exists)
```

## Episode detail flow (async)

1. `route()` calls `viewEpisode(e)` for `#e-<nr>`
2. `viewEpisode` sets `app.innerHTML = '<p class="loading">Laden…</p>'`
3. `await fetchEpisodeDetail(e)` — fetches `data/episodes/{key}.json`, merges all fields (including `e.an`) into `e`, sets `e._loaded = true`; uses a `_EP_FETCH` promise cache to deduplicate concurrent calls
4. `const T = await fetchTranscript(e)` — fetches `data/transcripts/{key}.json`, merges `e.an` into the raw JSON, calls `buildTFromRaw(raw, e)`, stores in `TX[key]`; returns `null` if no transcript exists
5. `app.innerHTML = viewEpisodeHTML(e, T, ...)` — renders the full page; passes `T` (or `null`) to tab generators
6. `mountTx(e, T)` — wires up the player and tab switching

**Critical:** `TX[key]` is set **after** `fetchEpisodeDetail` completes. If `fetchTranscript` is somehow called before `e.an` is set, the analysis merge is skipped and chapters/summary_points will be missing. The current code does `await fetchEpisodeDetail(e)` first, so this should not happen on a fresh page load.

## `buildTFromRaw(raw, e)` — the transcript T-object

Takes the raw `data/transcripts/{key}.json` (after `e.an` has been merged into it) and returns the `T` object the views consume:

```javascript
T = {
  D,          // duration in seconds
  spk[],      // per-speaker stats: {name, role, c, time, share, wpm, words, turns,
              //   longest, longestSeg, ttr, tics{}, questions}
  segs[],     // {i, sp, t, start, end, dur}  sp→spk entry
  chapters[], // {j, start, end, title, sum, who[]}
  laughs,     // always []  (Azure doesn't produce laugh events)
  interrupts, // always 0   (Azure doesn't produce overlap events)
  energy[80], // speech-density curve: fraction of each 1/80th window occupied by speech
  tldr,       // from analysis summary_tldr, or fallback to first 2 segment texts
  points[],   // from analysis summary_points (empty if no analysis)
  hls[],      // highlights from analysis, plus computed "Langste monoloog"
  bible[],    // {b, t}  from analysis bible_refs
  god,        // count of "God" / "god" in all segment text
  ment[],     // always []  (mention extraction not wired yet)
  bingo[],    // {b, hit, t}  from BINGO phrase list
  _isReal,    // always true (fake data generator removed)
  _hasAnalysis, // true when e.an was present and merged
  _hasChapters, // true when analysis provided real chapters (raw.chapters.length > 0 before fallback)
}
```

**Fallback chapter:** when `_hasChapters` is false, one synthetic chapter spanning the full duration is inserted so the chapters tab renders without crashing. The tab shows "beschikbaar zodra de analyse klaar is" instead of a chapter list.

## Tab structure on the episode page

The four tabs are built by separate functions:

| Tab | Function | Requires |
|---|---|---|
| Overzicht | `ovHTML(e, T, desc)` | T (shows river + description without T) |
| Hoofdstukken | `chHTML(e, T)` | T + `_hasChapters` |
| Transcript | `trHTML(e, T)` | T |
| Analyse | `anHTML(e, T)` | T + `_hasAnalysis` for most tiles |

## Key helper functions

```javascript
esc(s)           // HTML-escape; always use for user/data text in template literals
slug(s)          // lower-case, accents stripped, non-alphanum → "-"
norm(s)          // lower-case, accents stripped (for search matching)
wre(term)        // RegExp for word-start match of term (for search highlighting)
ts(s)            // seconds → "h:mm" or "m:ss" timestamp string
nl(n)            // number → Dutch formatted (1234 → "1.234")
tbtn(t)          // timestamp button HTML (seeks player on click)
riverHTML(T)     // speaker-colour river SVG
energySVG(T)     // speech-density energy curve SVG
segsHTML(T, q)   // searchable transcript segment list HTML
fragHits(e, q)   // transcript fragment hits for search results (uses TX cache)
```

## Search

The search system uses a TF-IDF cosine vector per episode (pre-computed at page load) plus:
- `norm()` for accent-insensitive matching
- `wre(term)` for word-start `RegExp`s
- Transcript hits via `fragHits(e, q)` — reads `TX[e.key]` only if already cached (no auto-fetch on search)

The search filter fieldset has a "Transcripten" toggle that shows/hides transcript fragment results. The state is `state.tx` (default: false).

## Theming

Colours come exclusively from CSS custom properties in `design-system/tokens.css`. Two dark-mode blocks must stay in sync with the light `:root` block:
1. `@media (prefers-color-scheme: dark)` — OS-level dark mode
2. `:root[data-theme="dark"]` — explicit dark toggle

A `data-theme` attribute on `<html>` overrides the OS preference. The theme toggle button sets this attribute and stores the preference in `localStorage`.
